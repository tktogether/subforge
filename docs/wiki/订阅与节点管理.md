# 订阅与节点管理

SubForge 把「节点从哪来」「节点如何归组」「规则指向哪个组」「客户端用哪条地址拉取」这四件事拆成独立但相互衔接的模块：机场与自建节点提供节点，分组决定策略组结构，规则决定分流，订阅令牌把前三者组合成一条可长期复用的订阅地址。

本页说明这些模块的数据结构、接口语义与相互依赖，适合需要长期维护多来源节点的管理员阅读。所有字段名、状态码与行为均取自源码，并标注来源位置。

## 1. 概念与存储

### 1.1 术语

| 术语 | 含义 |
| --- | --- |
| 机场 | 一条订阅来源，包含订阅地址、流量与节点数等元数据 |
| 订阅地址 | 机场提供的上游 URL，SubForge 从该地址拉取节点 |
| 节点 | 从上游解析出的单条代理配置 |
| 自建节点 | 手工登记的节点，以分享链接形式保存 |
| 分享链接 | `ss://`、`vmess://` 等标准 URI 形式 |
| 分组 | 输出到客户端配置中的策略组 |
| 规则 | 分流条目，其目标指向某个分组 |
| 规则集 | 一组可批量启停的规则集合 |
| 令牌 | 订阅访问凭证，一个令牌对应一条订阅地址 |
| 产物 | 转换后输出的配置文本 |

### 1.2 存储位置与前置条件

订阅管理依赖 SQLite 数据库，只有启动时提供了数据目录才会启用。直接运行的二进制需要显式指定 `-data-dir` 或设置环境变量 `SUBFORGE_DATA_DIR`；官方容器镜像（v0.1.4 起）已预设 `SUBFORGE_DATA_DIR=/data`，无需额外参数（`cmd/subforge/serve.go:194-282`）。四个启动选项都支持环境变量默认值，分别是 `SUBFORGE_LISTEN`、`SUBFORGE_TOKEN`、`SUBFORGE_CONFIG` 与 `SUBFORGE_DATA_DIR`，优先级为「环境变量 < 命令行参数 < INI 配置文件同名项」（`cmd/subforge/serve.go:113-123`、`:130`）。数据目录不要求预先存在，目录不存在时会自动创建（`cmd/subforge/serve.go:394-398`）。未提供数据目录时，本页涉及的管理接口统一返回 503 与 `{"error":"订阅管理未启用"}`（`internal/api/subscription.go:42-48`），启动日志也会打印一行提示（`cmd/subforge/serve.go:280-281`）。

主要数据表在首次启动时自动创建（`internal/store/store.go:440-584`）：

## 2. 机场管理

### 2.1 字段说明

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `id` | 整数 | 自增 | 机场标识 |
| `name` | 字符串 | — | 机场名称，导入规则时用于生成来源标记 |
| `subscription_url` | 字符串 | — | 订阅地址，为空时该机场不参与订阅生成 |
| `remarks` | 字符串 | 空 | 备注 |
| `enabled` | 布尔 | `true` | 是否启用 |
| `upload` / `download` | 整数 | 0 | 已用上传与下载流量，单位字节 |
| `total` | 整数 | 0 | 总流量，0 表示无限 |
| `expire` | 整数 | 0 | 到期时间，Unix 秒，0 表示未知 |
| `node_count` | 整数 | 0 | 最近一次刷新得到的节点数 |
| `traffic_at` | 整数 | 0 | 最近一次成功刷新流量的时间 |
| `traffic_err` | 字符串 | 空 | 最近一次刷新失败的原因 |

### 2.2 常用操作

新增机场使用 `POST /api/airports`，请求体字段为 `name`、`subscription_url`、`remarks`、`enabled`，成功返回 201 与 `{"airport":{...}}`（`internal/api/subscription.go:71-106`）。列表为 `GET /api/airports`，单项操作为 `GET`、`PUT`、`DELETE /api/airports/{id}`，删除成功返回 `{"ok":true}`。

刷新流量有三种入口：`POST /api/airports/refresh` 刷新全部启用机场，`POST /api/airports/{id}/refresh` 刷新单个机场，`POST /api/airports/refresh?with_rules=1` 在刷新后顺带导入规则（`internal/api/traffic.go:107-174`）。

```mermaid
sequenceDiagram
  participant A as 控制台
  participant B as SubForge 服务
  participant C as 上游订阅
  A->>B: POST /api/airports/refresh
  B->>C: 拉取订阅并读取流量信息
  C-->>B: 节点内容与 subscription-userinfo
  B->>B: 更新流量字段与节点数
  B-->>A: results ok fail
```

刷新的写入语义：成功时覆盖流量字段并清空 `traffic_err`；失败时只写入 `traffic_err`，保留上一次成功的流量数据，不会清零（`internal/subforge/subforge.go:149-162`）。

### 2.3 订阅可用性检测

`POST /api/airports/check` 对机场发起可用性检测，请求体可带 `{"ids":[1,2]}` 指定机场；未指定时对「启用且配置了订阅地址」的机场执行。响应为 `{results, ok, fail, at}`，结果包含 `name/url/ok/status_code/latency_ms/bytes/err`；`GET /api/airports/check/last` 返回最近一次结果。空集合返回 400 与「没有可检测的机场」，指定了不存在的机场返回 400 与「机场 N 不存在」。检测结果保存在进程内存中，服务重启后失效。

### 2.4 从订阅导入规则

`POST /api/airports/{id}/import-rules` 会拉取该机场订阅、解析内容并导入其中的规则与规则集，返回 `{rules_added, rules_skipped, providers_added, warnings}`（`internal/api/import_rules.go:26-90`）。导入的来源标记为 `airport:<机场名称>`，便于后续按来源批量管理。机场不存在返回 404，上游拉取或解析失败返回 502 与「导入失败: …」。

导入的规则默认是候选状态（`enabled=0`），需要批量启用后才会进入订阅产物。机场规则指向的是机场自己的分组名，这些名字通常没有建在「分组」页里；此时无需手工创建分组，系统按下面的顺序把目标映射到模板实际提供的分组（`internal/render/ruletarget.go`）：

1. 名字归一化后相等，例如 `📺 Netflix` 与 `🎥 Netflix` 视为同一个分组；
2. 一方是另一方子串且长度足够，例如 `📺 Emby影院` 命中 `🎥 Emby`；
3. 关键词对照，例如 `Apple` 命中 `🍎 苹果服务`、`🌏 国内直连` 命中 `🎯 全球直连`、广告类命中 `REJECT`；
4. 都匹配不到时落到兜底分组，即 `MATCH` 规则的目标。

映射了多少条、降级了多少条会作为警告出现在响应里，也会写进服务日志（`X-Convert-Skipped` 计数）。要精确分流时，先在「分组」页建同名分组，映射就会自动让位给完全匹配。

## 3. 自建节点管理

自建节点以分享链接保存，字段为 `link`、`name`、`enabled`（`internal/api/subscription.go:499-543`）。新建与修改都会做入库前校验（`internal/api/subscription.go:143-160` `validateSelfNode`）：名称或链接为空、链接解析失败、解析出的节点字段校验不通过，都会返回 400，错误文案形如「名称不能为空」「分享链接不能为空」「分享链接格式不正确：…」——**链接不合法时保存会直接报错，不会静默入列表**。

支持的分享链接协议包括 vmess、vless、trojan、ss、ssr、hysteria、hysteria2、tuic、anytls、socks5 与 http；不支持的协议会被跳过并计入产物的跳过计数（`docs/compatibility.md:304-356`）。自建节点与机场节点在转换时合并输出，来源顺序为机场在前、自建节点在后（`internal/convert/engine.go:135-168`），去重按「类型 + 服务器 + 端口 + 协议凭据」的指纹保留首次出现的节点（`internal/model/model.go:60-62`、`:156-161`）。

```mermaid
flowchart LR
  A[机场节点] --> C[合并节点列表]
  B[自建节点] --> C
  C --> D[按指纹去重并保留首个]
  D --> E[进入分组与规则阶段]
```

## 4. 分组管理

### 4.1 字段说明

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 字符串 | — | 分组名称，会出现在客户端配置中 |
| `type` | 字符串 | `select` | 分组类型 |
| `regex` | 字符串 | 空 | 成员匹配正则，非空时按正则选出节点 |
| `url` | 字符串 | 空 | 检测地址，仅对测速类分组有意义 |
| `interval` | 整数 | 0 | 检测间隔，单位秒 |
| `sort_order` | 整数 | 0 | 输出顺序 |
| `include_self` | 布尔 | false | 订阅渲染时是否在成员末尾追加方案选中的自建节点 |
| `include_all_sources` | 布尔 | false | 订阅渲染时是否把方案里所有机场的节点并入该组 |

接口为 `GET`、`POST /api/groups` 与 `GET`、`PUT`、`DELETE /api/groups/{id}`（`internal/api/subscription.go:154-239`）。

机场导入时，若某个分组的成员覆盖了该机场的全部节点（例如守候网络的「守候网络」），会自动打开 `include_self` 与 `include_all_sources`：订阅生成时该组不再只包含本机场节点，而是扩展到当前方案选中的所有机场；自建节点仍由 `include_self` 单独控制。子集组（例如只含香港节点）保持原成员不变。

### 4.2 类型支持面

同一份分组配置在不同目标格式下的可用类型并不相同，配置前应确认目标格式：

| 目标格式 | 支持情况 | 来源 |
| --- | --- | --- |
| Clash 系（mihomo） | 仅 `select`、`url-test`、`fallback`、`load-balance`，其他类型直接报错 | `internal/render/clashmeta/clashmeta.go:293-312` |
| sing-box | `select`、`relay`、`direct`、`pass` 映射为 selector，`url-test` 映射为 urltest，`fallback` 退化为 selector 并告警 | `internal/render/singbox/singbox.go:545-563` |
| Surge、Quantumult X、Loon、Surfboard | 无 fallback 类型时返回空并计入告警，`relay`、`balanced`、`sniffer` 无法表达 | `internal/render/lineform/formats.go:63-80` |
| Mellow | `select` 映射为 static，`url-test` 映射为 latency，`fallback` 映射为 fallback | `internal/render/mellow/mellow.go:218-255` |

### 4.3 统一最终选择组

多个机场、模板和规则源叠加到同一份订阅时，每个来源往往各带一个「最终节点选择组」：ikuuu 是 `🔰 选择节点`，守候网络是 `Lite Connect`，Aethersailor 是 `🚀 手动选择`。它们并列存在时，切换出口要在多个组里分别操作，规则源的选择目标还可能经兜底落到别的机场的选择组上。

订阅方案可以开启「统一最终选择组」，把这些来源最终组收敛为一个组。配置保存在 `profiles.final_group`（JSON 文本），Web 端在方案弹窗的「统一最终选择组」区块维护：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | false | 总开关；关闭时产物与未启用该功能完全一致 |
| `mode` | `auto` | `auto` 恒用标准名 `🚀 节点选择`；`custom` 使用 `name` |
| `name` | `🚀 节点选择` | 自定义统一组名；`auto` 模式下只用于界面回显 |
| `include_direct` | true | 统一组是否包含 `DIRECT` |
| `keep_source_terminals` | false | 是否把来源最终组保留为统一组的子选项 |
| `overrides` | `{}` | 按来源覆盖识别：`group:<source>` 指定来源最终组，`rule:<规则源名>` 指定规则源选择目标；值为 `["none"]` 表示不处理该来源 |

识别规则（`internal/render/finalgroup.go`）：

- 机场分组与模板分组按来源统计「被同来源其他分组引用」的入度，结合名字里的选择语义（节点选择/手动选择/Proxy/Select/Connect 等）与成员节点覆盖率；低置信来源会跳过，等待人工覆盖。
- 规则源没有分组树，按规则目标名与 FINAL/MATCH 兜底目标识别；Aethersailor 的 `🚀 手动选择` 就是靠目标名识别。
- 统一组默认包含当前产物里的全部节点 + `DIRECT`；服务组（Netflix、ChatGPT、国内服务等）保留，只把成员里对来源最终组的引用改为统一组。
- 全局 `MATCH` 指向统一组；原来落到模板兜底组（名称为 `🐟 漏网之鱼`）的规则也直接落到统一组，未被引用的兜底组会被剪枝。
- 关闭开关即可恢复原产物；来源分组本身不被修改或删除。

预览接口 `POST /api/profiles/{id}/final-group/preview` 接收草稿 `final_group`，返回每个来源识别到的最终组、依据、规则源选择目标、将被删除的分组与改写计数；Web 方案弹窗的「预览识别结果」按钮调用它。预览弹窗里可以逐来源改选或忽略最终组，也可以在规则源表格里填写选择目标覆盖（逗号分隔，留空恢复自动识别）。预览不展开模板层、也不执行订阅剪枝时会给出提示，实际产物分组数可能更少。

启用后，来源最终组与模板兜底组被合并为统一组，服务组改为引用统一组，未被引用的分组被剪枝，节点数与规则条数保持不变。逐项计数记录在 `docs/reports/` 下的验证报告中。

## 5. 规则与规则集

### 5.1 规则字段

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `rule_type` | 字符串 | — | 规则类型，例如 `DOMAIN-SUFFIX` |
| `rule_param` | 字符串 | — | 规则参数，例如域名后缀 |
| `rule_config` | 整数 | 0 | 目标分组 ID；为 0 时改用 `raw` 里保留的原始规则行，由渲染阶段映射目标 |
| `resolve_dns` | 布尔 | `true` | 是否附加 `no-resolve` |
| `enabled` | 布尔 | `true` | 是否启用 |
| `source` | 字符串 | 空 | 来源标记，手工新增为空，导入时为 `airport:<名称>` |
| `sort_order` | 整数 | 0 | 输出顺序 |

列表接口 `GET /api/rules` 会在每条规则上附加 `group_name`，由 `rule_config` 映射得到分组名，便于在界面上直接看到目标（`internal/api/subscription.go:243-273`）。订阅生成时，`rule_config` 指向的分组存在就输出 `规则类型,规则参数,目标分组`，`resolve_dns` 为真时追加 `,no-resolve`；`rule_config` 为 0 则输出 `raw` 里保留的原行，目标名交给渲染阶段按名称映射（`internal/api/subscription.go:682-706`）。走模板路径时，控制台启用的规则会与模板里的规则合并，规则在前、模板规则在后（`internal/convert/chain.go:55-61`）。

### 5.2 批量操作

`POST /api/rules/bulk` 用于批量启停，请求体为 `{ids, source, enabled}`：`ids` 与 `source` 必须二选一，同时给出或都不给出都会返回 400（`internal/api/rules_bulk.go:11-71`）。按来源批量操作适合在导入规则后统一关闭不需要的条目。

### 5.3 规则集

规则集由 `GET /api/rule-providers` 列出，支持按 `source` 与 `enabled` 过滤；`PUT /api/rule-providers/{id}/enabled` 用于启停，请求体必须是 `{"enabled": true|false}`，否则返回 400（`internal/api/ruleproviders.go:12-76`）。规则集的生成与版本管理见[规则工厂与规则源](规则工厂与规则源)。

## 6. 订阅令牌与订阅地址

### 6.1 令牌字段

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `token` | 字符串 | 自动生成 | 留空时由服务端生成 16 字节随机数的 32 位十六进制串 |
| `name` | 字符串 | 空 | 令牌名称 |
| `target` | 字符串 | 空 | 目标格式，空表示按请求推断或使用默认值 |
| `pipeline` | 字符串 | 空 | 命名管线 |
| `config` | 字符串 | 空 | 配置模板引用 |
| `include` / `exclude` | 字符串 | 空 | 逗号分隔的包含与排除正则 |

接口为 `GET`、`POST /api/tokens` 与 `GET`、`PUT`、`DELETE /api/tokens/{token}`（`internal/api/subscription.go:346-451`）。更新采用部分更新语义：省略的字段保持原值，显式传空串表示清空（`internal/api/subscription.go:415-451`）。令牌不存在时返回 404 与「令牌 x 不存在」。

### 6.2 订阅地址与参数优先级

订阅地址形如 `http://<主机>/subscribe?token=<令牌>`，控制台按 `origin + '/subscribe?token=' + encodeURIComponent(token)` 拼接（`web/src/api/endpoints.ts:470-472`）。该路由使用订阅令牌自行鉴权，因此不受服务端全局令牌约束：鉴权中间件对 `/subscribe` 精确豁免（`internal/api/server.go:295-328`）。

生成订阅时的取值优先级为：请求中的显式查询参数 > 令牌字段 > 回落链。其中目标格式回落到 `clash.meta`，管线回落到配置表中的 `subscribe.pipeline`（`internal/api/subscription.go:560-748`）。

```mermaid
flowchart LR
  A[请求查询参数] --> D[合并定制项]
  B[令牌字段] --> D
  C[默认回落值] --> D
  D --> E[读取启用机场与自建节点]
  E --> F[套用分组与规则]
  F --> G[渲染产物文本]
```

### 6.3 生成行为

每次请求都实时读取机场、分组与规则并重新编译，不生成静态文件（`internal/api/subscription.go:465-471`）。响应类型为 `text/plain; charset=utf-8`；订阅名会写入配置注释头的 `配置名:`，并通过 `profile-title` 与 `Content-Disposition` 响应头返回，供客户端显示订阅名称。名字优先级为：令牌名 > 方案名 > 服务名；中文名在 `profile-title` 里使用 `base64:`，文件名同时提供 ASCII 回退与 `filename*=UTF-8''`（显示名不带扩展名，避免客户端把 `.yaml` 当成订阅名）。若流量策略可用，响应会附带 `Subscription-Userinfo` 头，只统计启用、配置了订阅地址且有过流量刷新的机场。

流量头的聚合方式由流量策略决定，策略保存在配置键 `traffic.strategy` 中，可通过 `GET`、`PUT /api/traffic/strategy` 读写，`GET /api/traffic/preview?strategy=<JSON>` 可在不保存的情况下预览结果（`internal/api/traffic.go:18-49`、`:176-209`）。预设有 sum、min、max、avg、first、last、min_quota、max_quota、weighted 与 off（`internal/traffic/traffic.go:124-148`）。

### 6.4 与 `/sub` 转换端点的差异

两个入口都产出配置文本，但定位不同，不应混用：

| 维度 | `/sub` 转换端点 | `/subscribe` 订阅入口 |
| --- | --- | --- |
| 鉴权方式 | 服务端令牌（未设置令牌时不鉴权） | 订阅令牌 |
| 主要参数 | `target`、`url`、`include`、`exclude` 等转换参数 | `token` 与目标格式等五个定制字段 |
| 目标格式取值 | query 参数，缺省时按 User-Agent 推断 | query 参数 > 令牌字段 > `clash.meta` |
| 产物响应头 | `Content-Disposition`、`X-Convert-Format`、`X-Node-Count` 等 | `Subscription-Userinfo`，不写 `Content-Disposition` |
| 内容类型 | 按目标格式决定 | 固定 `text/plain; charset=utf-8` |
| 适用场景 | 临时转换与调试 | 长期使用的客户端订阅地址 |

`/sub` 的响应头与目标推断细节见 `internal/api/handlers.go:46-109`，`/subscribe` 的取值优先级见 `internal/api/subscription.go:560-748`。

## 7. 操作示例

新增一个机场并刷新：

```bash
curl -X POST http://127.0.0.1:25500/api/airports \
  -H 'Content-Type: application/json' \
  -d '{"name":"示例机场","subscription_url":"https://example.com/sub?token=abc","enabled":true}'

curl -X POST 'http://127.0.0.1:25500/api/airports/refresh?with_rules=1'
```

创建令牌并拉取订阅：

```bash
curl -X POST http://127.0.0.1:25500/api/tokens \
  -H 'Content-Type: application/json' \
  -d '{"name":"客厅路由","target":"clash.meta"}'

curl 'http://127.0.0.1:25500/subscribe?token=<YOUR_TOKEN>'
```

## 8. 注意事项

- 订阅地址中的令牌即访问凭证，泄露后应删除该令牌并重新创建。
- 机场与自建节点都为空时，订阅生成返回 400 与「没有启用的订阅或自建节点」。
- 机场刷新失败不会清空历史流量数据，但界面上的流量可能已经过期，应结合 `traffic_err` 判断。
- 可用性检测结果与最近一次检查时间保存在内存中，服务重启后需要重新执行。
- 分组的类型支持面取决于目标格式，`relay` 等类型在 mihomo 上会直接导致转换失败。
- 规则的 `rule_config` 是分组 ID 而不是分组名称，取值错误会静默落到 `DIRECT`。
- 数据目录决定本页接口是否可用：直接运行的二进制在不提供 `-data-dir` 或 `SUBFORGE_DATA_DIR` 时全部返回 503；官方容器镜像的 `v0.1.4` 及之后标签已默认启用，更早的标签需要显式传参。
