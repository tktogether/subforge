# v0.1.5 发布验证报告

- **日期**：2026-10-20
- **适用版本**：v0.1.5（提交 `e484e37d`）
- **结论**：四条控制台／引擎断层修复在发行产物中全部生效。控制台里自建的分组管线可以正常参与转换，机场在上游不返回流量头时按成功处理并写回节点数，规则源更新返回逐源结果，INI 规则源的内联 `[]` 规则集可以展开成规则行；镜像仍为双架构、自带版本号。

---

## 1. 验证范围

本次发布修复的是"控制台能操作、引擎却不认账"这一类断层，需要确认的是：

1. 在控制台创建的管线，走 `/api/convert` 与 `/sub?pipeline=` 是否都能转换成功（此前固定 502）；
2. 上游不返回 `Subscription-Userinfo` 时，机场是否仍被判定为采集成功，节点数是否写回；
3. 规则源更新全部失败时，HTTP 响应是否带逐源错误；
4. INI 规则源里的内联规则集（`[]GEOSITE`、`[]GEOIP`、`[]FINAL`）是否能展开；
5. 默认规则源清单是否不再指向一个不存在的地址；
6. 以上改动是否影响镜像的开箱即用、双架构与版本注入。

### 4.2 四条修复的实测结果

**控制台管线参与转换。** 用 `POST /api/pipelines` 建一条只保留香港节点的管线，再以 `pipeline=<名称>` 调 `POST /api/convert`：

| 请求 | v0.1.4 及更早 | v0.1.5 |
| --- | --- | --- |
| 不带 `pipeline` | 200 | 200 |
| 带控制台管线 | 502 `未找到命名管线` | **200** |

**机场流量不再误报失败。** 用一个不返回 `Subscription-Userinfo` 的真实机场刷新：

```json
{"fail":0,"ok":1,"results":[{"airport_id":1,"name":"shouhou","ok":true,
  "node_count":45,"err":"",
  "note":"上游未提供 subscription-userinfo：本次只更新了节点数，流量信息保持未知"}]}
```

刷新后机场行的 `node_count` 为 45（修复前固定为 0，且 `traffic_err` 非空）。

**规则源更新返回逐源结果。** 依次执行 `POST /api/rule-sources/init`、`POST /api/rule-sources`（`input_format` 为 `ini`）、`POST /api/rule-sources/update`，响应 200 并带三条结果，`err` 均为空：

```json
{"results":[
  {"source":"reject","version":"20261020-071018","err":""},
  {"source":"private","version":"20261020-071018","err":""},
  {"source":"Custom_Clash_Full","version":"20261020-071018","err":""}]}
```

其中 `Custom_Clash_Full` 就是此前 56 个规则集全部拉取失败的 INI 规则源。

## 5. 已知取舍与遗留

1. **`v0.1.4` 及更早的标签仍带这四条缺陷**，需要在 `192.168.8.102` 上升级到 `v0.1.5`（裸二进制或镜像）后才会消失；GHCR 上的历史标签不会重建。
2. **`-scratch` 标签仍不含根证书**，只适合上游全部为 `http://` 或本地文件的场景。
3. **INI 内联规则集不支持嵌套 `[]` 子表达式**，取值按「类型 + 一项参数」解释（`[]GEOSITE`、`[]GEOIP`、`[]FINAL`），Aethersailor 的配置属于这一类；更复杂的嵌套写法需要先补解析器。
4. **规则工厂的 `format:` 字段仍未生效**（既有问题，与本次修复无关），决定落盘扩展名的是 `output.format`。
5. **未在真实 OpenWrt 设备上验证** `opkg install` 与 procd 拉起。

## 6. 复现方式

```bash
docker run --rm ghcr.io/tktogether/subforge:v0.1.5 version
docker manifest inspect ghcr.io/tktogether/subforge:v0.1.5

docker run -d --name sf15 -p 25500:25500 -e SUBFORGE_TOKEN=<YOUR_TOKEN> \
  ghcr.io/tktogether/subforge:v0.1.5
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:25500/
curl -s -H "X-Token: <YOUR_TOKEN>" http://127.0.0.1:25500/api/pipelines
```

验证环境：WSL2 Ubuntu 22.04，Docker 29.1.3（overlayfs 存储驱动），16 vCPU。
